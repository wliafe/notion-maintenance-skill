# Notion MCP：检查与连接

本参考只处理**当前客户端已提供的 Notion MCP**（官方 Notion 插件、工作区连接或等价服务）。技能通过搜索、读取、更新类工具读写 Notion；具体工具名与命名空间以本次会话实际暴露为准。

## 先确认当前客户端与现状

先检查本次会话提供的 MCP 工具及当前客户端的有效配置，再决定是否需要安装或授权。

| 检查结果 | 应采取的动作 |
| --- | --- |
| 已有 Notion 搜索/读取类工具 | 用只读搜索或读取做一次轻量验证；成功则继续任务。 |
| 配置存在，但当前会话没有工具 | 核对启用状态、重新加载 MCP、登录/授权是否过期；不能据此判定未安装。 |
| 服务已禁用、被拒绝或受管理策略限制 | 说明具体状态；不自动启用或绕过限制。 |
| 工具可调用但返回无权限/找不到工作区 | 说明授权或工作区范围问题；请用户在客户端完成 Notion 授权并确认目标工作区。 |
| 确认当前客户端没有 Notion MCP | 按该客户端官方方式安装或启用 Notion 连接；缺少授权时说明缺项，一次询问是否安装/连接。 |

区分“配置存在”“客户端尚未加载”“只读调用已响应”三种证据。只有最后一种可报告 Notion MCP 可用。不要用会改写页面的更新工具做连接健康检查。

仅为当前已确认的客户端与工作区操作。仅触发本技能或要求整理 Notion，不自动授权安装新插件或扩大工作区访问范围。

## 常见能力映射

不同客户端工具名可能不同，按描述选择等价能力：

- **搜索**：按标题或关键词查找页面/数据库
- **读取**：获取页面正文、子页面与属性
- **更新**：按最小范围修改页面内容或属性
- **创建**（若任务需要且手册允许）：新建页面或数据库行

调用前阅读该工具的参数说明；不要编造未暴露的参数或端点。

## 安装与授权原则

- 优先使用客户端内置的 Notion / Notion Workspace 连接或官方文档中的 MCP 安装方式。
- 需要 OAuth 或浏览器登录时，由用户完成授权；Agent 不代替输入密钥到不可信位置。
- 写入前确认目标工作区与用户意图一致；连错工作区时停止修改并说明。
- 权限不足时报告实际错误，不反复重试同一失败调用。

## 故障排查顺序

1. 当前会话工具列表中是否出现 Notion 相关工具。
2. 只读搜索或读取是否返回预期工作区内容。
3. 客户端 MCP 面板中的连接、启用、错误日志。
4. 用户是否对目标页面有编辑权限。

仍失败时，保留已确认事实，给出用户可执行的下一步（重新授权、重载 MCP、检查工作区），不把连接失败说成“手册不存在”。
