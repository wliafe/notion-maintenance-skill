# 默认：从对话更新工作台

本参考约定技能的**默认任务**：用户点名本技能且消息里**没有其它可执行提示词**时，根据**当前对话**与**近期相关对话**，按入口页「使用说明」更新工作台。具体写什么、写到哪一分区，一律以已读「使用说明」为准；本文件不规定归属细则。

## 何时走默认路径

同时满足：

1. 本技能被点名（例如 `/notion-maintenance-skill` 或客户端等价选择）。
2. 用户消息里除技能点名外，**没有**其它可执行提示词（未指定页面、分区、禁止范围或具体整理目标）。

若同一次消息在技能名之外还有具体要求，以那些提示词为准：可仍用下文方式收集对话材料，但**不**自动扩大成全工作台同步。

未点名本技能时，不因本参考而主动同步。

## 收集对话材料

1. **当前对话**：归纳已确认事实、决策、可复用方法、待办与卡点；区分「已证实」与「推测/计划」。
2. **近期对话**：若客户端提供会话搜索或历史检索，用与当前主题相关的少量关键词各搜一轮（避免一次塞太多词导致无结果）；优先近期、与工作台维护相关的会话。仅根据标题与可见摘要判断相关性，需要细节时再打开对应会话。
3. **无会话搜索时**：只用当前对话与用户本轮粘贴的材料；向用户说明未能检索近期对话，不编造历史。
4. 整理成待写入候选清单：每条写清来源（当前对话 / 某次近期对话标题）、证据强度、可能归属分区（仅作进入手册后的线索，不代替「使用说明」）。

## 再按手册写入

1. 按 [查找「使用说明」](finding-usage-guide.md) 定位入口（优先标题含「工作台」）及将改动的分区，完整阅读相关「使用说明」。
2. 用「使用说明」中的归属与确认规则过滤候选清单：手册不允许或证据不足的条目不写；应落在项目页的不写进通用分区。
3. 写入前搜索并阅读将改动的现有内容；同一主题优先局部更新，做最小修改。
4. 写入后回读，按「使用说明」中的完成检查核对。

## 向用户汇报

简要说明：

- 用了哪些当前/近期对话材料（标题或范围即可）
- 读了哪些「使用说明」
- 实际改了哪些页面、跳过了哪些候选及原因
- 回读结论

把“已收集对话”“已读手册”“已写入”“已回读”分开据实说明。
